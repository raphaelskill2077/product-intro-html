# Product Intro HTML

将用户提供的产品资料整理成一套适合展示和讲解的 HTML 产品介绍。

核心流程：

**读取资料 → 生成大纲 → 用户确认 → 补全图片 → 生成 3 个封面方案 → 用户确认风格 → 生成完整 HTML → 检查最终渲染结果**

## Step 1｜读取产品资料

读取用户提供的：

- 产品介绍 PDF / PPT / 文档
- 产品图片
- 产品参数
- 产品视频
- 品牌资料
- 其他相关素材

理解产品并提取：

- 产品是什么
- 核心定位
- 用户痛点
- 核心卖点
- 使用场景
- 关键数据 / 参数 / 产品证据

不要编造资料中不存在的产品功能、参数、数据或效果。

## Step 2｜生成 5 页核心大纲

根据产品资料，固定按照以下结构生成大纲：

1. **这是什么**：产品名 + 一句话定位 + 产品主图
2. **为什么需要**：一句核心痛点 + 使用场景图
3. **最厉害什么**：1 个核心卖点 + 2～3 个辅助卖点
4. **怎么用**：真实使用场景 + 简单使用流程
5. **凭什么相信**：关键数据 / 参数 / 产品证据

每一页都需要明确：

- 页面标题
- 核心文字
- 使用什么图片 / 视觉
- 基本排版方式

完成大纲后：

**先交给用户确认，不要直接生成完整 HTML。**

## Step 3｜检查并补全资料

生成大纲后，检查完成这 5 页需要的资料是否齐全。

如果缺少必要的：

- 产品信息
- 参数
- 数据
- 产品图片
- 品牌资料

请用户补充。

如果缺少的是：

**使用场景图 / 真实使用场景图**

则可以主动调用 Image 2.5 等可用图像生成工具进行生成。

生成场景图时：

- 参考用户提供的真实产品图片
- 尽量保持产品外观、颜色、比例和结构一致
- 场景必须与产品功能和使用方式相关
- 不随意修改产品设计
- 不添加不存在的功能

## Step 4｜用户确认大纲

把完整的 5 页内容结构和需要使用的图片告诉用户。

等待用户确认或修改。

用户确认后：

**再进入视觉设计阶段。**

## Step 5｜生成 3 个封面设计方案

大纲确认后，使用 Frontend Slides 的设计原则生成 HTML 封面。

使用真实产品内容和产品图片，设计：

**3 个明显不同的封面方案。**

三个方案需要在以下方面有明显区别：

- 排版
- 字体
- 配色
- 背景
- 产品构图
- 视觉氛围

不能只是简单换颜色。

先展示 3 个封面方案：

**不要立即生成完整 HTML。**

等待用户选择视觉方向。

## Step 6｜生成完整 HTML

用户确认封面风格后：

按照选中的视觉方向，正式生成完整 HTML Presentation。

整套 HTML 统一：

- Typography
- Color
- Grid
- Spacing
- Background
- Product Image Style
- Motion

设计遵循 Frontend Slides 的原则：

- 一页一个重点
- 少文字
- 大产品图
- 强视觉层级
- 统一对齐
- 适当留白
- 背景与产品相关
- 动效服务于内容
- 保持 Presentation 感

默认采用：

**16:9 / 1920 × 1080**

不要生成普通官网、Dashboard 或 Card 式网页。

## 文字与排版规则

- 一页只讲一个重点。
- 标题简短，正文尽量控制在 2～3 行。
- 同级卖点原则上不超过 3 个。
- 不要为了塞入更多信息缩小字体。
- 中文标题必须按照语义自然断行。
- 禁止出现孤字、孤立标点或明显不自然的断句。
- 禁止出现一行只有 **1～2 个字** 的短尾行。

如果标题出现不自然断行，优先调整：

1. 换行位置
2. 文字区域宽度
3. 文案长度
4. 产品图与文字区域比例
5. 字号

不要为了维持原来的版式强行断字。

## Frontend Slides 设计原则

使用 Frontend Slides 的设计思路，但不需要把产品介绍做成普通 PPT 或网页模板。

重点保留：

- **Distinctive Design**：设计应来自产品本身、目标受众和展示场景，避免通用模板感。
- **Show, Don't Tell**：用真实封面方案、产品图、场景图和视觉结构呈现方向，不只给抽象风格词。
- **Typography**：标题、正文、数字和标签建立清晰层级；中文字体必须有可靠回退。
- **Color & Theme**：用统一主题变量控制色彩、背景、文字和动效，避免默认紫色渐变。
- **Visual Hierarchy**：一屏一个重点，让产品和核心卖点先被看见。
- **Motion**：动效快速、顺滑、有节奏，只服务内容理解。
- **Progressive Disclosure**：先呈现核心价值，复杂参数和细节按需展开或放在证据页。
- **Atmospheric Background**：背景有氛围，但不能抢产品，也不能影响可读性。
- **Meaningful Interaction**：交互只用于切换、展开、查看细节或辅助理解，不做产品 Demo。

## Final Render Check

**HTML 生成完成后，必须主动检查最终渲染结果，而不是只检查 HTML / CSS 代码。**

逐页检查：

- 是否存在一行只有 1～2 个字
- 是否存在孤字
- 是否存在孤立标点
- 标题断句是否自然
- 文字是否溢出
- 图片是否被异常裁切
- 元素是否重叠
- 标题、正文和图片是否对齐
- 产品是否足够突出
- 页面是否存在明显视觉失衡

如果发现孤字、短尾行或不自然换行：

**必须重新排版。**

可以调整：

- 文案
- 手动换行位置
- 文本框宽度
- 字号
- 行距
- 产品图大小
- 左右布局比例

修改后：

**重新渲染并再次检查。**

执行：

**生成 → 渲染 → 视觉检查 → 修正 → 再渲染 → 最终交付**

只有最终渲染结果排版自然、没有明显问题后，才输出给用户。

## Final Standard

最终产品介绍应该让观众快速回答：

**这是什么？**

**为什么需要？**

**它最厉害的是什么？**

**怎么用？**

**凭什么相信？**

整个 Skill 最重要的原则：

> **先确认讲什么，再确认长什么样，最后才生成完整 HTML。**
